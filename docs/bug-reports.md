## BR-01: StorageError сложно воспроизвести вручную
- **Связанный тест-кейс:** TC-21
- **Приоритет:** средний
- **Шаги воспроизведения:**
  1. Заполнить localStorage через консоль.
  2. Попробовать добавить карточку.
- **Ожидаемый результат:** плашка «Хранилище переполнено».
- **Фактический результат:** в зависимости от размера данных — либо ошибка, либо запись проходит. Сложно подобрать размер для стабильного воспроизведения.
- **Причина:** размер данных при заполнении через консоль и через форму различается.
- **Решение:** в тест-кейсе TC-21 добавлена альтернатива — симуляция через `throw new StorageError(...)`.
- **Статус:** закрыт (не баг, документация уточнена)
- **Исполнитель:** Широков

## BR-02: `renderCardsList` использует innerHTML без экранирования
- **Связанный тест-кейс:** TC-01
- **Приоритет:** высокий
- **Шаги воспроизведения:**
  1. Добавить карточку с иероглифом `<img src=x onerror=alert(1)>`.
  2. Карточка отрисуется, тег выполнится.
- **Ожидаемый результат:** данные экранируются, тег не выполняется.
- **Фактический результат:** возможен XSS через иероглиф/перевод.
- **Причина:** `list.innerHTML = cards.map(...)` в `app.js`, без `escapeHtml`.
- **Решение:** использовать `textContent` или добавить функцию экранирования.
- **Статус:** открыт
- **Исполнитель:** —
