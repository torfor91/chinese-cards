# Стратегия ветвления проекта

## Дата: 05.10.2026
## Команда: Широков, Толоконникова

## Выбранная стратегия: GitHub Flow

## Обоснование

Проект небольшой (2 разработчика), без сложного релизного цикла. GitHub Flow — оптимальный выбор:
- `main` — стабильная версия, всегда рабочая.
- `feature/*` — новые функции.
- `bugfix/*` — исправления.
- `release/*` — подготовка релиза.

## Правила

1. Любая новая функция — в отдельной ветке от `main`.
2. Коммиты — осмысленные, с префиксом (`feat:`, `fix:`, `docs:`, `test:`, `NC-*`, `BR-*`).
3. После завершения — слияние в `main` (или Pull Request).
4. `main` всегда рабочая: тесты зелёные, CI проходит.
5. Перед релизом — ветка `release/vX.Y` для финальных правок.

## Использованные ветки

| Ветка | Назначение | Статус |
|---|---|---|
| `main` | Стабильная версия | активна |
| `feature/modules` | Разработка модулей (день 4) | слита |
| `feature/validation-module` | Модуль валидации | слита |
| `release/v1.0` | Подготовка релиза | активна |

## Разрешённые конфликты

Конфликтов при слиянии не возникло: ветки разрабатывались параллельно и касались разных модулей. В случае конфликта — слияние вручную с сохранением обеих правок.
